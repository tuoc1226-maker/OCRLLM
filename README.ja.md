## モデルのコンテキストサイズ

本アプリケーションは、コスト効率と高性能を重視した複数の埋め込み（embedding）モデルおよびチャットモデルをサポートしています。一貫性を保つため、埋め込みベクトルは1,024次元に切り詰められ、ドキュメントは500トークン単位のチャンクに分割して処理されます。

| プロバイダー | モデル                       | 次元数     | 最大トークン数 | 価格 ($ / 100万トークン) |
|--------------|------------------------------|------------|----------------|--------------------------|
| **OpenAI**   | text-embedding-3-small       | 1,536      | ~8,191         | $0.020                   |
|              | text-embedding-3-large       | 3,072      | ~8,191         | $0.130                   |
| **Google**   | gemini-embedding-001         | 3,072      | 2,048          | *非公開*                 |
|              | text-embedding-preview-0409  | 768        | 2,048          | $0.025                   |
| **Mistral**  | mistral-embed                | 1,024      | 32,768         | $0.010                   |

**推奨事項**: OpenAIの `text-embedding-3-small` および `gpt-4o-mini` は、ほとんどのユースケースにおいてコスト効率が高く、信頼性にも優れています。大規模なドキュメントの場合、QdrantやDgraphとの互換性を確保するため、チャンクは8,000トークンの制限内で処理されます。 **2025年7月31日時点**: 検索（リトリーバル）用に `Qwen3-Embedding-0.6B` と `Qwen3-30B-A3B`（非思考型/Instructモデル）を試してみたいと考えています。その性能には本当に驚かされました。Qwenチームは素晴らしい仕事を成し遂げました。vLLMにはOpenAI互換のエンドポイントが用意されているため、実質的に「プラグアンドプレイ」で利用できるはずです。実際に試すことになれば、Docker関連の構成ファイルなどを共有する予定です。

### 利用例
企業の文書群（在庫受領書、給与明細、公共料金の請求書など）をカテゴリ別に整理します。「在庫関連の支出を要約して」といったカテゴリ別のプロンプトを使用し、モジュール化された要約を生成してPostgreSQLに保存します。これらの要約とマスタープロンプト（例：「店舗での支出額はいくらか？」）を組み合わせ、`gpt-4o-mini`（コンテキストウィンドウ128,000トークン）を用いて、一貫性のあるハイブリッドな回答を生成します。

## 概要

OCRLLMは以下の要素を組み合わせています：
- 📚 **セマンティック検索**: OpenAIモデルを使用した埋め込み（Embedding）ベースの検索。
- 🧠 **グラフベース検索**: Dgraphを使用したエンティティ（実体）と関係性のインデックス作成。
- 💬 **LLMによる回答**: OpenAIのチャットモデルを使用し、出典を明記した正確な回答を生成。
- 📊 **ハイブリッド検索**: ベクトルの類似性とエンティティの関係性を組み合わせ、精度の高い結果を提供。

文書は解析・クレンジング（OCR処理を考慮）され、500トークン単位のセグメントに分割（チャンク化）された後、埋め込み処理を経て、Qdrant（ベクトル用）およびDgraph（エンティティ/関係性用）にインデックス化されます。

## 特徴

- 🗃 **対応フォーマット**: `.pdf`, `.txt`, `.doc(x)`, `.xls(x)`, `.csv`, `.jpg`, `.png`, `.heic`, `.webp`, `.md`, `.rtf`, `.odt`, `.ods`
- 🔄 **変換**: 専用のパーサーを使用して文書をMarkdown形式に変換。
- ✂️ **チャンク化と埋め込み**: Markdownをトークン化し、500トークン単位のセグメントに分割。埋め込みはOpenAIを使用して生成。
- 🧾 **メタデータ保存**: プレビュー用に、ファイルのメタデータとBase64形式のコンテンツをPostgreSQLに保存。 - 🔍 **検索**: `/search` エンドポイントは、セマンティック検索とグラフベースのクエリを組み合わせたハイブリッド検索をサポートしています。
- 💬 **チャット**: `/chat` エンドポイントは、参照元を明記した回答を提供します。「マスターチャット」（全ドキュメント対象）と「カテゴリチャット」（特定のカテゴリ対象）の両方に対応しています。
- 🧠 **ナレッジグラフ**: `/knowledge_graph` エンドポイントは、高度なクエリ実行のためにノードとエッジを公開します。
- 🔒 **セキュリティ**: すべてのエンドポイントで `X-API-Key` による認証が必要です。
- 🚀 **非同期処理**: パフォーマンス向上のため、OCRやファイルアップロードの処理はCeleryが担います。
- 👁 **プレビュー**: `/preview/{file_id}` を介して、アップロードされたファイルをプレビューできます。
- 🗂 **カテゴリ**: ユーザー定義のカテゴリとカスタムプロンプトを使用して、ドキュメントを整理・分類できます。

## デプロイ手順

1. リポジトリをクローンします:
```bash
git clone https://github.com/tuoc1226-maker/OCRLLM.git
cd OCRLLM
```
2. 環境変数を設定します:
```bash
cp env_example .env
```
`.env` ファイルを編集し、OpenAI APIキー、PostgreSQL設定、その他の構成情報を入力してください。
3. アプリケーションを起動します:
```bash
docker compose up -d --build
```
